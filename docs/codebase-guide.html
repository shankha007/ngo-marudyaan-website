📸Add a gallery project (photo album)A new album on the Gallery page, up to 5 photos▶
public/images/projects/<id>/src/data/projects.jspastWorks.js (optional)
  1. Pick an idYear first, lowercase, dashes: 2025-puja-drive. It becomes the folder name and the link /gallery#2025-puja-drive.
  2. Copy the photos inRun this in the project folder. It renames them 01.jpg…05.jpg, skips duplicates and stops at five. 
    npm run add-photos -- "C:\Users\me\Downloads\Puja 2025" 2025-puja-drive
    Or make the folder public/images/projects/2025-puja-drive/ and drop the files in yourself.
  3. Add a block to projectsOpen src/data/projects.js and paste this at the top of the projects list. The id must match the folder exactly. 
    // src/data/projects.js → inside  export const projects = [ … ]
{
  id: "2025-puja-drive",
  year: 2025,
  category: "festival",          // education | festival | winter
  cover: "03.jpg",               // optional: defaults to the first photo
  title: { en: "Puja Drive", bn: "পুজোর উদ্যোগ" },
  summary: { en: "What happened…", bn: "কী হয়েছিল…" },
  captions: {                    // optional, one per photo
    "01.jpg": { en: "Caption", bn: "ক্যাপশন" },
  },
},
  4. Link it (optional)To show the album on a past work, set project: "2025-puja-drive" on that work in pastWorks.js. To use it as a programme's photo, set project: on the programme in content.js.
  5. Check itnpm run dev → open /gallery. Then npm test.
FieldRequired?Meaning
idyesFolder name in public/images/projects/
yearyesShown on the album; albums sort newest first
categoryyeseducation, festival or winter: sets the Gallery filter
covernoFile name of the photo used on Home and About
captionsnoPer photo; a photo without one uses the title

Swap a photo: delete the one you don't want from the folder (and its caption), then add the new file. A sixth photo is ignored, and npm test reports which album has too many.

  1. Create the page filesrc/pages/MyPage.jsx: 
    import PageHeader from "../components/PageHeader";
import { site } from "../data/site";
import { useLang } from "../i18n/LanguageContext";
import usePageMeta from "../hooks/usePageMeta";

export default function MyPage() {
  const { t } = useLang();
  usePageMeta(`${t("mypage.title")} — ${site.name}`, "English description for search engines.");

  return (
    <>
      <PageHeader title={t("mypage.title")} sub={t("mypage.sub")} />
      <section className="container-page py-16">
        <p className="text-ink-2">{t("mypage.intro")}</p>
      </section>
    </>
  );
}
  2. Register the routeIn src/App.jsx: import it at the top, then add the route above the path="*" line. 
    import MyPage from "./pages/MyPage";
// …inside <Routes>, above the "*" route:
<Route path="/my-page" element={<MyPage />} />
  3. Tell Netlify it's a real pageIn public/_redirects, add a line with the other pages, above the /* line. Without it, the page works but reports "404" to search engines. 
    /my-page        /index.html   200
  4. Add it to the sitemapIn public/sitemap.xml: 
    <url><loc>https://marudyaan.com/my-page</loc></url>
  5. Add the labels in both languagesIn src/i18n/strings.js, add the keys to the en block and the bn block. 
    // in en: { … }
"nav.mypage": "My Page",
"mypage.title": "My Page",
"mypage.sub": "A short line under the title",
"mypage.intro": "Opening paragraph.",

// in bn: { … }
"nav.mypage": "আমার পাতা",
"mypage.title": "আমার পাতা",
"mypage.sub": "শিরোনামের নিচের লাইন",

  6. Put it in the menus (optional)Add the same line to links in src/components/Navbar.jsx and to quickLinks in src/components/Footer.jsx: 
    { to: "/my-page", key: "nav.mypage" },
  7. Check itnpm test. The navigation suite fails if App.jsx, _redirects and sitemap.xml don't list the same pages.
Rules for the new page: exactly one <h1> (PageHeader gives you it), no hard-coded English (use t() or tr()), and <Photo> instead of <img>.

Writing in two languages

Every piece of visible text exists in English and Bengali. There are two kinds:

Content

In src/data/*.js

Written as an object with both languages, right where it's used:

title: { en: "Winter drive", bn: "শীতবস্ত্র কর্মসূচি" }

Code reads it with tr(item.title).

Labels

In src/i18n/strings.js

A key in the en block and the same key in the bn block:

// en  "nav.donate": "Donate",
// bn  "nav.donate": "দান করুন",

Code reads it with t("nav.donate").

Forgot the Bengali? The site falls back to English rather than showing a blank, but the a11y test flags English leaking into Bengali mode. Outgoing form emails are always English, on purpose.

Test and publish

  1. Start the site locally 
    npm run dev
    Open http://localhost:5173. It reloads every time you save. First time on a new computer, run npm install first.
  2. Check both languagesClick the English / বাংলা toggle in the header and look at what you changed.
  3. Run the tests 
    npm test
    Use npm run test:quick for a faster check. Warnings about placeholders are fine; failures need fixing.
  4. Commit and push to uat 
    git switch uat
git add -A
git commit -m "Add the 2025 Puja drive album"
git push
  5. Open a pull request from uat into main 
    gh pr create --base main --head uat
  6. Merge itOnce the source-branch-is-uat check passes, merge. Netlify rebuilds and the live site updates in a minute or two.
You can't push to main directly. It's protected, and pull requests from any branch other than uat are blocked.

How the forms work

Contact, Get Involved and Request Help all follow the same path:

Visitor clicks Sendpage's onSubmit
→
ValidateBad fields are outlined, the error is shown, focus moves to the first bad field
→
useFormSender.send()Is there a Web3Forms key?
No key

Email app opens

A mailto: link with the message filled in, plus a WhatsApp fallback.

Key → success

Sent to the inbox

POST to Web3Forms. A success box, and the form clears.

Key → failure

Fallback links

"Send on WhatsApp" and "Send by email", carrying the same message.

Spam trap: a hidden "botcheck" checkbox. People never see it; if a bot ticks it, the form pretends to succeed and sends nothing.

The test suites

npm test builds the site and drives your real Chrome/Edge through every page. Tests read their expectations from the data files, so content edits don't break them.

🔥 smoke

Every page × every screen size × both languages: no errors, no broken images, no overflow, one <h1>.

🧭 navigation

The three page lists match; links, anchors and the saved language work.

🧪 features

Albums match folders, max 5 photos, lightbox, copy buttons, UPI, forms, FAQ. Warns about placeholders.

⚡ performance

WebP copies, lazy loading, no layout jumps, banner photo first.

♿ a11y

Carousel pause, focus traps, skip link, no English labels in Bengali mode.

🏷️ netlify-badge

Live only: Netlify's badge never covers a button.

House rules
